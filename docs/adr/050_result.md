# 050. Обобщённый Result

**Статус:** принято.

## Контекст
Обработчик возвращает успех с данными, «не найдено» (`404`) или отказ с причиной (`409` + `reason`). Отказы ожидаемы и часты: например, `capacity-exceeded` на популярном занятии.

## Решение
Свой `Result<T>` в `BusinessLogic`: `Success(T)`, `NotFound`, `Conflict(ConflictReason)`.

- Причины отказа — перечисление `ConflictReason`. Строка контракта задаётся атрибутом `[JsonStringEnumMemberName("capacity-exceeded")]` (.NET 9) на каждом значении.
  - `JsonStringEnumConverter` сериализует значение в `reason` строкой контракта.
  - Метод расширения `ToCode()` читает тот же атрибут — для логов и тестов. Строка задаётся в одном месте.
  - Произвольную строку передать нельзя, `switch` проверяет полноту.
  - Переопределить `ToString()` у `enum` в C# нельзя, поэтому `ToCode()`.
- `BaseApiController` переводит `Result` одним методом:
  - успех → `200` или `201`;
  - `NotFound` → `404`;
  - `Conflict` → `409` и `ProblemDetails` с полем `reason` верхнего уровня.
- Исключения остаются для настоящих сбоев. Их ловит существующий `ExceptionHandlingMiddleware` и отдаёт `500`.

## Последствия
- Все исходы видны в сигнатуре, тесты проверяют результат, а не перехватывают исключения.
- Откат транзакции при отказе естественный: коммит не вызывается ([060](060_transactions.md)).

## Отклонённая альтернатива
- «Умное перечисление» (класс со статическими экземплярами и своим `ToString()`): нет проверки полноты `switch`, нужен свой JSON-конвертер.
Исключения `BusinessRuleException` и `NotFoundException`: это управление потоком через исключения и дорого под нагрузкой.
