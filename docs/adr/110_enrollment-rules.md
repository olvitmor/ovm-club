# 110. Правила брони: записаться, изменить, отменить, карточка

**Статус:** принято.

## Общий принцип порядка проверок
Когда подходят несколько причин отказа, проверяем **от постоянного к временному**:
1. состояние занятия;
2. абонемент;
3. вместимость.

Вместимость — единственная причина, которая может уйти сама, поэтому её клиент видит последней: значит, имеет смысл встать в очередь.

Нечисловой id в пути — `400`: маршрут без ограничения `{id:long}`, иначе было бы `404`. Обязательные поля тела nullable и `[Required]`: отсутствующий `classId` не превращается в `0` и `404`. Числа в теле разбираются строго: `"classId": "1"` — `400`, хотя веб-настройки System.Text.Json по умолчанию такое принимают.

## 1. `POST /enrollments`
`400` (формат, `seats < 1`, нет `Idempotency-Key`) → повтор по ключу ([070](070_idempotency.md)) → `404` → `class-cancelled` → `class-started` → `pass-expired` → `pass-exhausted` → `capacity-exceeded` → бронь создана, посещения списаны.

Запись открыта до самого начала занятия.

## 2. `POST /enrollments/{id}/seats`
`400` → `404` (нет или чужая) → `enrollment-cancelled` → `class-cancelled` → `class-started` → далее по направлению изменения:

| Изменение | Проверки | Действие |
|---|---|---|
| увеличение | `pass-expired` → `pass-exhausted` → `capacity-exceeded` | списать разницу |
| без изменений | — | `200`, ничего не меняется |
| уменьшение | не проверяются (возможно при просроченном или исчерпанном абонементе) | вернуть разницу на абонемент в любой момент до начала; **передать освободившиеся места очереди** ([120](120_waitlist.md)) |

Ответ — полная карточка, как в разделе 4.

## 3. `POST /enrollments/{id}/cancel`
1. `404` — нет или чужая.
2. Уже отменена → `200` с сохранённым результатом, ничего не меняется.
3. Занятие отменено клубом → полный возврат в любой момент, даже после начала. Перевода из очереди нет.
4. Занятие началось → `409 class-started`.
5. До начала не меньше `RefundCutoff` (2 ч) → полный возврат, иначе `0`.
6. Места освобождаются всегда → перевод из очереди, если она ещё открыта ([120](120_waitlist.md)).

**Новая колонка `enrollments.refunded_visits` (int, null у активных).** Повторная отмена обязана вернуть тот же `refundedVisits`, а пересчитать его при повторе нельзя: граница в 2 часа могла уже пройти. Сиды заполняют колонку для отменённых броней по тому же правилу из `cancelled_at` и `starts_at`.

## 4. `GET /enrollments/{id}`
`404` для чужой и несуществующей брони. Отменённая бронь и бронь на отменённое клубом занятие отдаются как есть. Выборка — с `IgnoreQueryFilters()`, иначе глобальный фильтр `!IsCancelled` скроет такие брони. Кэш — [090](090_card-cache.md).

## Возврат при уменьшении брони
Разница возвращается всегда, без границы в 2 часа: этого требует контракт («уменьшение… возвращает разницу на абонемент»).

**Известная лазейка:** уменьшить бронь с 3 до 1 за 10 минут до начала выгоднее, чем отменить (там возврат 0). С точки зрения бизнеса стоит применять к уменьшению то же правило `RefundCutoff`, что и к отмене, но это изменение контракта. Вынесено в [NOTES](../../NOTES.md).
