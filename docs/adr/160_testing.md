# 160. Тесты

**Статус:** принято.

## Контекст
Задание требует покрыть тестами контроллер, добавленные методы репозиториев и собственные сервисы. Тестовый проект на MSTest уже есть: `WebApplicationFactory` и отдельная база на каждый прогон. Подключён Moq.

## Решение

| Уровень | Что | Как |
|---|---|---|
| Интеграционные (контроллеры) | все 8 ручек: коды, `reason`, форма ответа, 401/403/429 | `ApiApplicationFactory`, настоящие Postgres и Redis |
| Репозитории | новые методы: блокирующие выборки, подсчёт мест, расписание, аналитика, очередь | прямо на тестовой БД |
| Обработчики и политики | правила возврата, выбор кандидатов из очереди, порядок причин | юнит-тесты, Moq для зависимостей |
| Конкурентность | параллельные запросы на последнее место и последнее посещение; одинаковый ключ идемпотентности | N одновременных запросов, проверка инвариантов |

**Данные — каждый тест создаёт свои:** помощник `Given` пишет прямо в тестовую БД (`Given.Class(capacity: 2, startsIn: 3h)`, `Given.User(visits: 5)`).
- тесты не зависят от сидов, которые привязаны к моменту первого запуска;
- каждый тест получает своих пользователей: тесты изолированы и не упираются в лимит частоты.

**Время — `FakeTimeProvider`** (`Microsoft.Extensions.TimeProvider.Testing`), подменяется в фабрике. Границы `RefundCutoff` и `WaitlistCloseBefore` проверяются точно, до секунды.

**Ограничитель:** в фабрике большой `PermitLimit`. Отдельные тесты с маленьким лимитом проверяют `429`, запасной уровень (Redis подменён падающим) и предохранитель.
