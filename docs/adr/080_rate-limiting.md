# 080. Ограничение частоты

**Статус:** принято.

## Контекст
«Не более 60 запросов в минуту от одного пользователя суммарно по всем восьми эндпоинтам». 61-й запрос в пределах минуты получает `429`. Значит, окно скользящее: любые 60 секунд, а не календарная минута.

## Решение

### Где в конвейере
Фильтр ресурса MVC `UserRateLimitFilter`, атрибутом на контроллерах восьми ручек:
- **после** аутентификации и авторизации: запрос без токена получает `401` и лимит не расходует;
- **до** привязки модели: запросы с ответом `400` тоже считаются;
- `/auth/login` и `/health` не ограничиваются.

### Уровень 1 — Redis, скользящее окно
Ключ `ratelimit:{userId}` — sorted set. Один атомарный Lua-скрипт на запрос:
```lua
local t = redis.call('TIME')
local now = t[1] * 1000 + math.floor(t[2] / 1000)
redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, now - ARGV[1])
if redis.call('ZCARD', KEYS[1]) >= tonumber(ARGV[2]) then
  local oldest = redis.call('ZRANGE', KEYS[1], 0, 0, 'WITHSCORES')
  return oldest[2] + ARGV[1] - now
end
redis.call('ZADD', KEYS[1], now, ARGV[3])
redis.call('PEXPIRE', KEYS[1], ARGV[1])
return 0
```
- время берётся из Redis, а не из приложения: часы экземпляров могут расходиться;
- отклонённые запросы не записываются, иначе клиент, повторяющий запросы после `429`, никогда не разблокируется;
- скрипт возвращает 0, если запрос разрешён, иначе — через сколько миллисекунд освободится место.

### Уровень 2 — память процесса, только при сбое Redis
`PartitionedRateLimiter` с `SlidingWindowRateLimiter` по `userId`, тот же лимит. Простаивающие разделы удаляются автоматически.

### Предохранитель
После ошибки Redis 30 секунд не опрашиваем его и сразу используем уровень 2. Иначе каждый запрос ждал бы таймаута соединения.

### Ответ
`429` с `ProblemDetails` и заголовком `Retry-After` — точное число секунд до освобождения места.

## Последствия
- В запасном режиме лимит действует на каждый экземпляр отдельно: при N экземплярах до N×60 запросов. Это приемлемая деградация.
- При возврате на Redis счётчики не переносятся, возможен кратковременный всплеск.

## Источник
Подход основан на статье [Implementing Rate Limiting in .NET with Redis](https://hamedsalameh.com/implementing-rate-limiting-in-net-with-redis-easily/) (вариант Lua sliding window). Отличия от статьи: ключ — пользователь, а не IP; фильтр на 8 ручках, а не промежуточное ПО на всё; время из Redis; ответ в формате `ProblemDetails`; добавлен запасной уровень.
