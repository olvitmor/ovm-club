# 120. Лист ожидания

**Статус:** принято.

## Модель
Таблица `waitlist_entries`:

| Колонка | Назначение |
|---|---|
| `id`, `user_id`, `class_id`, `seats`, `created_at` | запись очереди |
| `status` | `waiting` → `promoted` или `cancelled` |
| `enrollment_id` | бронь, в которую переведена запись (`promoted`) |
| `cancelled_at` | момент ухода из очереди |

Индексы:
- уникальный частичный `(user_id, class_id) WHERE status = 'waiting'` — «не больше одной записи в очереди», гарантия на уровне БД;
- `(class_id, created_at, id) WHERE status = 'waiting'` — порядок очереди и `position`.

Посещения при постановке в очередь **не списываются и не резервируются**. Списание происходит при переводе в бронь.

## 7. `POST /enrollments/waitlist`
`400` → повтор по ключу → `404` → `class-cancelled` → `class-started` → `waitlist-closed` → `already-waiting` → `seats-available` (свободных мест хватает) → запись создана.

`position` — число ожидающих этого занятия с `(created_at, id)` не больше собственного, начиная с 1.

Абонемент при постановке **не проверяется**: в контракте очереди нет причин `pass-*`, и его могут пополнить, пока человек ждёт. ⚠️ Решение вынесено на обсуждение ([NOTES](../../NOTES.md)).

## 8. `POST /enrollments/waitlist/{id}/cancel`
`404` (нет или чужая) → уже `cancelled` → `200`, ничего не меняется → `promoted` → `409 already-promoted` → `status = cancelled`.

Почему `409`: ответ «`cancelled`» был бы неправдой, у клиента уже активная бронь. Отменять её нужно через ручку 3 по её правилам.

## Перевод из очереди
Вызывается внутри транзакции отмены брони или уменьшения мест, на уже заблокированном занятии ([020](020_locking.md)).

1. Занятие отменено клубом или очередь закрыта (`now >= starts_at − WaitlistCloseBefore`, по умолчанию 1 час) → перевода нет.
2. `free` = вместимость − места активных броней (**все** свободные места, а не только освобождённые этой операцией).
3. Кандидаты — ожидающие с `seats <= free`, по порядку `(created_at, id)`. Их абонементы и абонемент инициатора блокируются одним запросом по возрастанию id.
4. Идём по очереди. **Первый подходящий получает места:** если первому нужно больше, чем свободно, места получает следующий, кому хватает, а первый остаётся первым.
5. Абонемент просрочен или посещений меньше `seats` → **пропускаем, запись остаётся ждать** (абонемент могут пополнить вне API).
6. Перевод: создаётся обычная активная бронь, списываются посещения, запись получает `promoted` и `enrollment_id`, `free -= seats`.
**Инициатор, который сам ждёт на этом занятии, переводится на общих правилах.** Возврат начисляется до перевода, поэтому вернувшиеся посещения можно сразу потратить на новую бронь. Например, Анна отменяет бронь на 2 места и стоит первой в очереди за 2 местами: места получает она, а не следующий в очереди.
7. После коммита сбрасываются версии кэша карточек переведённых пользователей ([090](090_card-cache.md)).

## Закрытие очереди за час до начала
Бизнес-цель: никто не получает неожиданную бронь за несколько минут до занятия.
- за `WaitlistCloseBefore` до начала перевод прекращается: отмена за 1,5 часа переводит ожидающих, за 50 минут — нет;
- встать в очередь после закрытия нельзя: `409 waitlist-closed`;
- записи не трогаем, фоновой обработки нет. Уйти из очереди можно по-прежнему;
- освободившиеся после закрытия места остаются свободными для обычной записи, которая открыта до начала.

## Свои причины отказа
| `reason` | Ручка | Когда |
|---|---|---|
| `waitlist-closed` | 7 | до начала меньше `WaitlistCloseBefore` |
| `already-promoted` | 8 | запись уже переведена в бронь |

## Последствия
- Ожидающий с большим `seats` может долго не дождаться: места достаются тем, кому хватает.
- Человек, переведённый из очереди, получает обычную бронь со всеми её правилами, включая отмену без возврата меньше чем за 2 часа.
