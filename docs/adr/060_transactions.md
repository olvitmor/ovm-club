# 060. Транзакции в командах

**Статус:** принято.

## Контекст
Задание требует: «отказ не оставляет следов». Блокировки ([020](020_locking.md)) должны браться внутри уже открытой транзакции. Сброс кэша ([090](090_card-cache.md)) выполняется только после коммита.

## Решение
Каждый обработчик команды явно открывает транзакцию на `UnitOfWork.DbContext.Database` и коммитит её только при успехе. При отказе транзакция откатывается при `Dispose` (`await using`).

Действия до и после коммита тоже записаны в обработчике явно:
- перед коммитом — сохранение ответа под ключом идемпотентности ([070](070_idempotency.md));
- после коммита — сброс версии кэша карточек затронутых пользователей ([090](090_card-cache.md)).

## Последствия
- Каркас транзакции повторяется в обработчиках команд, зато весь сценарий виден в одном методе.
- Сброс кэша после коммита исключает гонку: если сбросить до коммита, параллельное чтение успеет закэшировать старые данные.

## Отклонённая альтернатива
Базовый класс обработчика с `BeforeCommitAction` и `AfterCommitAction`: при пяти командах он почти не убирает дублирования, но прячет транзакцию и порядок шагов из сценария.
