# 060. Транзакции в командах

**Статус:** принято, этап 1 из 2.

## Контекст
Задание требует: «отказ не оставляет следов». Блокировки ([020](020_locking.md)) должны браться внутри уже открытой транзакции. Сброс кэша ([090](090_card-cache.md)) выполняется только после коммита.

## Решение

### Этап 1 — сейчас
Каждый обработчик команды явно открывает транзакцию на `UnitOfWork.DbContext.Database` и коммитит её только при успешном `Result`. При отказе транзакция откатывается при `Dispose`.

### Этап 2 — после того как сценарии устоятся
Базовый класс обработчика команды:
- открывает транзакцию, вызывает абстрактный метод сценария, коммитит при успехе;
- `virtual BeforeCommitAction` — действия внутри транзакции перед коммитом (например, сохранение ответа под ключом идемпотентности);
- `virtual AfterCommitAction` — действия после успешного коммита (сброс версии кэша карточек).

## Последствия
- Этап 1 повторяет похожий код в пяти обработчиках, но держит сценарий на виду, пока правила обкатываются.
- Сброс кэша после коммита исключает гонку: если сбросить до коммита, параллельное чтение успеет закэшировать старые данные.
