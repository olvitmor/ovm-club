# План реализации

Каждый этап — законченный и проверяемый участок: сборка зелёная, тесты этапа проходят, всё, что работало раньше, продолжает работать. После проверки — отдельный коммит.

Общая проверка каждого этапа:
```
docker compose up -d
dotnet build
dotnet test
```

---

## 00. Окружение
- Установить .NET 9 SDK (сейчас на машине только SDK 10, а среды выполнения ASP.NET Core 9 нет).
- **Проверка:** `dotnet run --project WebApi` → `GET /health` возвращает 200, `POST /auth/login` выдаёт токен; `dotnet test` проходит (тестов пока нет).

## 01. Каркас
- Проект `BusinessLogic`, ссылки, запись в `.sln` ([030](adr/030_layers.md)).
- `Ovm.Cqrs` и регистрация обработчиков ([040](adr/040_cqrs.md)).
- `Result<T>`, перечисление `ConflictReason` с `ToCode()`, перевод `Result` в ответ в `BaseApiController` ([050](adr/050_result.md)).
- Классы настроек и секции `appsettings.json`, `ValidateOnStart` ([150](adr/150_configuration.md)).
- Регистрация `TimeProvider`.
- **Проверка:** юнит-тесты перевода `Result` в `200/201/404/409` с `reason`; каждое значение `ConflictReason` сериализуется в строку контракта; приложение стартует, неверная настройка роняет старт.

## 02. Время
- Привязчик даты и времени (время обязательно, перевод в UTC), строгий `DateOnly`, вывод с усечением до микросекунд ([100](adr/100_time.md)).
- **Проверка:** юнит-тесты привязчиков и конвертеров: без смещения, со смещением, только дата, мусор.

## 03. Схема и сиды
- Сущности `WaitlistEntry` и `IdempotencyKey`, колонка `Enrollment.RefundedVisits`, конфигурации, индексы.
- Миграция; сиды заполняют `refunded_visits` у отменённых броней ([110](adr/110_enrollment-rules.md)).
- Репозитории новых сущностей в `UnitOfWork`.
- **Проверка:** `docker compose down -v && docker compose up -d && dotnet run --project WebApi` — миграция и сиды применяются на чистой базе; тест: у каждой отменённой брони из сидов `refunded_visits` заполнен по правилу.

## 04. Тестовая обвязка
- `FakeTimeProvider` и переопределение настроек в `ApiApplicationFactory`.
- Помощник `Given` (зал, занятие, пользователь с абонементом, бронь, запись очереди) и получение токена для пользователя ([160](adr/160_testing.md)).
- **Проверка:** пробный тест: создать пользователя, войти, получить `401` без токена и `404` на несуществующий маршрут с токеном.

## 05. Репозитории: блокировки и подсчёт мест
- `LockClassAsync`, `LockPassesAsync` (одним запросом по возрастанию id), подсчёт занятых мест ([010](adr/010_seat-accounting.md), [020](adr/020_locking.md)).
- **Проверка:** тесты репозиториев: отменённое занятие находится при блокировке, сумма учитывает только активные брони, вторая транзакция ждёт блокировку.

## 06. Ручка 4 — карточка брони (без кэша)
- Запрос, контроллер, модель ответа ([110](adr/110_enrollment-rules.md)).
- **Проверка:** `200` со всеми полями; отменённая бронь; бронь на отменённое клубом занятие; чужая бронь — `404`; нечисловой id — `400`; без токена — `401`.

## 07. Ручка 1 — записаться (без хранения ключей)
- Команда с транзакцией и блокировками; заголовок `Idempotency-Key` пока только обязателен.
- **Проверка:** `201`; все `400`; `404`; каждая причина `409` и их порядок при нескольких сразу; отказ не меняет места и посещения; **параллельная запись на последнее место** — ровно одна бронь.

## 08. Ручка 2 — изменить число мест (без очереди)
- **Проверка:** увеличение и уменьшение; то же число мест — `200` без изменений; уменьшение при просроченном или пустом абонементе; уменьшение меньше чем за 2 часа — разница возвращается; все причины `409` и их порядок; ответ — полная карточка.

## 09. Ручка 3 — отменить бронь (без очереди)
- Колонка `refunded_visits`, граница `RefundCutoff`.
- **Проверка:** возврат за 2 часа и больше; `0` меньше чем за 2 часа (границу проверяем `FakeTimeProvider` до секунды); отменённое клубом занятие — полный возврат после начала; `409 class-started`; повторная отмена — тот же ответ.

## 10. Лист ожидания
- Ручки 7 и 8, перевод из очереди в ручках 2 и 3, закрытие очереди ([120](adr/120_waitlist.md)).
- **Проверка:** `position`; `seats-available`, `already-waiting`, `waitlist-closed`, `already-promoted`; перевод «первый подходящий»; пропуск при плохом абонементе; нет перевода после закрытия; уменьшение брони переводит ожидающих; юнит-тесты политики выбора кандидатов.

## 11. Идемпотентность
- Таблица ключей в ручках 1 и 7, фоновая очистка ([070](adr/070_idempotency.md)).
- **Проверка:** повтор — `201` и то же тело, без второй брони; другое тело — `409 idempotency-key-reused`; отказ не сохраняет ключ; одинаковый ключ у разных пользователей и ручек не конфликтует; **параллельные запросы с одним ключом** — одна бронь; очистка удаляет просроченные ключи.

## 12. Ручка 5 — расписание
- [130](adr/130_schedule.md).
- **Проверка:** все `400`; сортировка; обход всех страниц без пропусков и дублей при одинаковом времени начала; токен с другими фильтрами — `400`; `freeSeats` и `mySeats`; отменённые занятия скрыты; несуществующий зал — пустой список.

## 13. Ручка 6 — загруженность залов
- [140](adr/140_analytics.md).
- **Проверка:** `403` для пользователя; группировка по дню UTC (занятие в 23:30 и в 00:30); отменённые занятия и брони не учитываются; `to` включительно; все `400`.

## 14. Кэш карточки
- [090](adr/090_card-cache.md).
- **Проверка:** второе чтение берётся из кэша; после записи, изменения мест, отмены и перевода из очереди карточки **всех** затронутых пользователей актуальны; Redis недоступен — ответ из БД.

## 15. Ограничение частоты
- [080](adr/080_rate-limiting.md).
- **Проверка:** 60 запросов проходят, 61-й получает `429` с `Retry-After`; лимит у разных пользователей независим; `401` не расходует лимит; `/auth/login` не ограничен; падающий Redis — срабатывает лимит в памяти и предохранитель.

## 16. Нагрузочная проверка
- `scripts/load-seed.sql`, `scripts/load.js` ([170](adr/170_load-testing.md)).
- **Проверка:** засев с изменёнными переменными; прогон k6; инварианты после прогона; вывод по пересмотру [010](adr/010_seat-accounting.md) — дописываем в ADR.
